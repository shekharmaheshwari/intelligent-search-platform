Setup

First-time workspace setup, environment variables, and credential configuration.

First-time workspace setup

ISP runs entirely in Docker. Clone the repo, then use the provided deploy script:

# 1. Clone
git clone <repo-url> intelligent-search-platform
cd intelligent-search-platform

# 2. Copy and fill in the backend env file
cp backend/.env.example backend/.env
# (edit backend/.env — see Environment Variables section below)

# 3. Start everything
./deploy-api.sh

deploy-api.sh builds Docker images, starts all containers on the isp-net network, and waits for the API to become healthy. After it completes, the UI is available at http://localhost:3001 and the API at http://localhost:8001.

Subsequent deploys: run ./deploy-api.sh again to rebuild only changed layers. Docker build cache makes this fast.

Environment Variables

All variables go in backend/.env. The backend uses pydantic-settings with safe defaults for local Docker development — only the variables below are required for full functionality.

VariableRequiredDescription
VOYAGE_API_KEY Yes (for embeddings) Voyage AI API key used to generate 1024-dim embeddings. Get one at voyageai.com. Without this, ISP falls back to lexical-only search.
GOOGLE_SERVICE_ACCOUNT_JSON Yes (for GSheets) Single-line JSON of the Google service account key file. Must have no newlines. See the Google Sheets section below.
SECRET_PROVIDER No Where ISP reads secrets from. Options: env (default), vault, aws.
DATABASE_URL No PostgreSQL connection string. Defaults to the Docker Compose isp-db service: postgresql://isp:isp-dev-password@isp-db:5432/isp.
TYPESENSE_HOST No Typesense container hostname. Defaults to typesense (Docker service name).
REDIS_URL No Redis URL for the embedding cache and distributed job lock. Defaults to redis://isp-redis:6379.
EMBED_MODEL No Active embedding model. Defaults to voyage-3. Can also be set via PUT /v1/settings at runtime.

Example backend/.env

VOYAGE_API_KEY=pa-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
GOOGLE_SERVICE_ACCOUNT_JSON={"type":"service_account","project_id":"my-project",...}
SECRET_PROVIDER=env

SECRET_PROVIDER options

ValueDescription
env (default) Reads secrets directly from environment variables / .env file. Suitable for local development and single-host deployments.
vault Reads secrets from HashiCorp Vault. Requires VAULT_ADDR and VAULT_TOKEN (or a Vault agent sidecar) to be configured. ISP will fetch the secrets at startup.
aws Reads secrets from AWS Secrets Manager. Requires the container to have an IAM role or AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY in the environment. ISP fetches secrets by name at startup.

Google Sheets service account

The Google Sheets connector authenticates using a service account — no user OAuth flow is needed.

  1. Open the Google Cloud Console — Service Accounts.
  2. Click Create Service Account. Give it a name (e.g. isp-sheets-reader) and click through to completion — no special IAM roles are needed.
  3. Open the service account, go to the Keys tab, click Add key → Create new key → JSON. Download the .json file.
  4. Collapse the JSON to a single line (required — multi-line JSON will break the env var parser): 
    cat key.json | jq -c . > key_single_line.json
  5. Copy the single-line content into backend/.env: 
    GOOGLE_SERVICE_ACCOUNT_JSON={"type":"service_account","project_id":"my-project","private_key_id":"abc123","private_key":"-----BEGIN RSA PRIVATE KEY-----\n...","client_email":"isp-sheets-reader@my-project.iam.gserviceaccount.com",...}
  6. In Google Sheets, click Share on the spreadsheet you want to index. Add the client_email from the JSON (e.g. isp-sheets-reader@my-project.iam.gserviceaccount.com) with at least Viewer access.
  7. Restart the ISP API container for the new env var to take effect: docker compose restart isp-api.
Never commit the service account JSON to git. The backend/.env file is in .gitignore. For production, use SECRET_PROVIDER=vault or SECRET_PROVIDER=aws and store the JSON in your secrets manager.

Vault setup (optional)

If you are using HashiCorp Vault as your secret provider:

  1. Store your secrets in Vault at a path like secret/isp: 
    vault kv put secret/isp \
  VOYAGE_API_KEY="pa-xxx" \
  GOOGLE_SERVICE_ACCOUNT_JSON='{"type":"service_account",...}'
  2. Set the following in your environment (or container definition): 
    SECRET_PROVIDER=vault
VAULT_ADDR=https://vault.internal:8200
VAULT_TOKEN=s.xxxxxxxx
VAULT_SECRET_PATH=secret/isp
  3. ISP will read all keys from that Vault path at startup and inject them as environment variables. No changes to the application code are needed.
